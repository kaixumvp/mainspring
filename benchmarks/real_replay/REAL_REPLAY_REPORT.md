# 真实语料回放报告：考勤项目群聊（脱敏）

- 生成时间：2026-11-24 · 数据：`chat_log_anonymized.txt` · 脚本：`replay_real.py` · 原始数据：`real_replay_report.json`
- **诚实标注**：内容全真（人名→角色、手机号/验证码抹除）；**时钟合成**（话题切换 +5000 事件、对话重复 3 个 epoch、epoch 间 +50000）——真实日志只有一天，不合成时钟测不到「隔段时间回归」。
- **安全提示**：本目录含脱敏数据，分支有远程 origin，**勿推送到远端**；API Key 只走进程环境变量，未落盘。

## 发现一：写入选材误杀 90%（带回行里的重要发现）

mainspring 自带的 Reflector 打分在阈值 0.35 下滤掉了 **171/189** 条真实消息，
其中 6 条是业务关键结论：

```
✗ 没有用到考勤组，登陆人——》考勤档案——》统计方案——》考勤周期
✗ 薪福通逻辑是：修改当前加班规则，选择统计周期为当前周期的，则是当月周期（…）
✗ 修改规则后，再去进行手工核算日考勤，感觉会读到最新的打卡规则或加班规则吧？
✗ 不是当月，是统计方案的周期，你改统计方案的周期看过吗
```

**原因**：打分靠三条——长度（`split()` 数词，中文无空格＝1 个词）、偏好词、第一人称
（`\b` 词边界对汉字永远不匹配）。中文技术群聊三条全不中，得分 0.3 低于阈值 0.35。

**裁决**：规则打分对中文技术语料**不可用**。修复路线：换 LLM 打分，或修规则
（中文按字符数判长度 + 去掉 `\b`）。这是 mainspring 本身的缺陷，不在 BrainMemory 范围内，
但真实落地前必须先修——否则「什么值得记」这道门是坏的。

## 发现二：话题回归——机制在真实内容上成立（云 embedding 版，最终数字）

27 次探针（话题第 2 次出现起、每 epoch 一次，**先问后写**）：

| 话题 | 探针 | Brain 相关命中 | 冷层救援 | LRU 命中 |
|---|---|---|---|---|
| 考勤周期 | 3 | 3 | 2 | 1 |
| 规则核算 | 3 | 3 | 2 | 1 |
| 考勤组 | 3 | 3 | 3 | 0 |
| 回归测试 | 3 | 3 | 2 | 1 |
| **报表** | 3 | **3（哈希版 0）** | **3** | 0 |
| 验证码 | 3 | 3 | 3 | 1 |
| 权限 | 3 | 3 | 2 | 1 |
| 晚报 | 2 | 0 | 0 | 0 |
| 节假日 | 2 | 2 | 2 | 0 |
| 排班 | 2 | 2 | 2 | 0 |
| **合计** | **27** | **25（93%）** | **21（78%）** | **5（19%）** |

**白话**：隔段时间回到一个话题，BrainMemory 93% 记得（78% 是从冷层「想起来」的）；
LRU 只记得 19%。机制在真实业务内容上成立，赢面与合成基准方向一致。

自证：tier 分位 [0.0, 0.02, 0.11]、M' 分位 [0.05, 0.728, 0.798]、驱逐 255 次、提回 106 次。
性能：引擎 query p99 0.087ms、QPS 4.7 万（**不含 embedding 网络耗时**——本轮约 90 次云调用，
每条消息的向量只算一次，命中后走缓存）。

## 发现三：云 embedding 救回报表，剩晚报一个——失败原因已查明

哈希占位 vs 云 embedding（qwen3.7-text-embedding-flash）对比：

| 指标 | 哈希占位 | 云 embedding |
|---|---|---|
| 相关命中 | 22/27（81%） | **25/27（93%）** |
| 冷层救援 | 18 | **21** |
| 平均相似度（相关命中） | 0.265（字面重叠噪声） | **0.678（真语义分）** |
| 报表话题 | 0/3 | **3/3** |
| 晚报话题 | 0/2 | 0/2 |

- 哈希版报表失败 = 短查询 vs 长消息的余弦稀释 + 哈希碰撞 → **云模型已解决**；
- 晚报仍失败，原因与哈希版**不同**：探针「今天的bug晚报」里「bug」被语义模型放大，
  短消息「那这个是bug吗」（相似度 0.58）赢了 800 字的长日报——标题相似但正文全是
  统计表格，语义被稀释。**这是超长消息的工程问题，不是机制问题**：真实系统对
  长文要先分块（标题/摘要单独成条），或让探针贴近标题级表述。

**裁决**：上云 embedding 后 25/27（93%）vs LRU 5/27（19%）——语义召回与记忆机制
在真实语料上均已验证。剩余的 2 次失败有明确的工程对策（长文分块），无机制隐患。
